# Скилл: графика простых казуальных игр (igrasu.ru)

## 0. Как работать агенту (порядок действий)

1. **Прочитай игру**: движок (DOM/CSS или 2D-canvas), размер ассетов, список игровых событий (клик, совпадение, ошибка, победа, поражение, level-up, конец сессии).
2. **Составь карту событий** (раздел 3): какие из них сейчас не имеют отклика. Это главный фронт работ.
3. **Измерь базу** (раздел 9): вес ассетов, FPS, TTI. Без базовых цифр нельзя доказать, что стало не хуже.
4. **Правь по приоритету**: (а) первые 10 секунд → (б) фидбек на действия → (в) читаемость → (г) прогресс и награды → (д) стилизация.
5. **Измерь после**, пройди чек-лист (раздел 11), опиши коммит по шаблону.

Если задача звучит как «сделай красивее» — трактуй её как «сделай понятнее, отзывчивее и приятнее на 2-й, 5-й и 20-й минуте игры».

## 1. Принципы

1. **Удержание важнее красоты.** Изменение оправдано, только если улучшает: понятность первого действия, отклик, ощущение прогресса или желание сыграть ещё раунд.
2. **Стилизация, а не фотореализм.** Flat / semi-flat 2D с лёгкой искусственной глубиной. Запрещены: фотореалистичный 3D, PBR, тяжёлые шейдеры, высокополигональные модели, WebGL/3D-движок в игре, где сейчас DOM или 2D-canvas.
3. **Производительность — жёсткое ограничение, а не пожелание.** Аудитория — слабые мобильные, сессия «на 2 минуты».
4. **Ясность > детализация.** Игрок за 1 взгляд понимает: что кликабельно, где цель, сколько осталось, что произошло.
5. **Честность.** Графика не должна обманывать: запрещены фейковые кнопки, ложные «закрыть», визуальные приёмы, провоцирующие случайные клики по рекламе, «тёмные паттерны» давления (ложные таймеры, шейминг при выходе).

Если есть выбор между «визуально сложнее» и «проще, но отзывчивее и легче» — выбирай второе.

## 2. Первые 10 секунд (самый сильный рычаг удержания)

Большая часть отвала происходит до первого осмысленного действия.

- **Игровое поле видно сразу**, без обязательного меню, логотипов-заставок и «нажмите, чтобы начать» дольше 1 экрана. Допустима одна крупная кнопка «Играть».
- **Первое действие подсвечено**: пульсирующий контур/рука-подсказка на первой подходящей клетке или кнопке (opacity/transform-анимация, 1.2–1.6 с цикл). Подсказка исчезает после первого верного действия и больше не возвращается в этой сессии.
- **Никаких текстовых туториалов длиннее одной фразы.** Обучай действием: первые 2–3 хода делаются «по рельсам» с подсветкой.
- **Первый успех — за ≤ 5–8 секунд.** Первый уровень/раунд визуально и механически должен быть почти непроигрываемым и давать заметную награду (эффект раздела 3).
- **Скелетон/заглушка вместо пустого экрана**: пока грузятся ассеты, показывай фон и поле простыми фигурами, затем подменяй спрайтами без сдвига вёрстки (резервируй размеры, CLS = 0).
- **Критичные ассеты — первыми** (поле, тайлы, кнопка «Играть», звук клика). Экраны результатов и редкие анимации — lazy-load после старта.

## 3. Фидбек на события («game feel»)

Каждое событие из карты обязано иметь визуальный отклик. Минимальная таблица (значения — стартовые, подстраивай под игру):

| Событие | Визуальный отклик | Длительность | Блокирует ввод? |
|---|---|---|---|
| Касание/клик по элементу | первый кадр отклика ≤ 100 мс: scale 1→0.94→1.04→1, смена яркости/тени | 150–220 мс | нет |
| Верное действие/совпадение | пульс + вспышка + 6–12 частиц (искры/конфетти) | 200–350 мс | нет |
| Ошибка/неверное действие | короткая тряска по X (±4px, 2–3 колебания) + мягкая красная подсветка, без «наказывающих» эффектов | 200–300 мс | нет |
| Комбо/серия | эскалация: каждый шаг серии сильнее (больше частиц, ярче акцент, число-«x3» вылетает и затухает) | 250–400 мс | нет |
| Получение очков/монет | число «всплывает» вверх (translateY + opacity) от места действия; счётчик в HUD «тикает» и коротко пульсирует | 400–600 мс | нет |
| Прогресс-бар/цель | плавное заполнение (transform: scaleX), при заполнении — вспышка | 300–500 мс | нет |
| Победа/уровень пройден | разовый яркий эффект: конфетти/свечение + «ступенчатое» появление звёзд/наград (stagger 120–200 мс) | 800–1500 мс, **пропускается тапом** | только на время появления кнопок |
| Поражение | мягкое затухание поля, сразу крупная кнопка «Ещё раз» | 300–500 мс | нет |
| Почти победа («чуть-чуть не хватило») | показать, сколько не хватило (например, «осталось 2 клетки»), быстрый перезапуск | 300 мс | нет |

Правила:
- **Внутри игрового цикла анимации ≤ 400 мс.** Длиннее — только на экранах победы/награды, и они всегда пропускаются тапом.
- **Не блокируй ввод анимациями** там, где это не нужно по логике. Игрок не должен ждать.
- **Стэггер** при появлении групп элементов: 30–60 мс между элементами, суммарно ≤ 400 мс.
- **Переходы между экранами**: fade/slide 200–350 мс, easing `cubic-bezier(0.22, 1, 0.36, 1)` (ease-out), не linear.
- **Звук** синхронен с визуалом, файлы < 300 мс, общий звук можно выключить одной заметной кнопкой; по умолчанию звук стартует только после первого жеста пользователя.
- **Вибрация** (`navigator.vibrate(10–20)`) — опционально, только на ключевые события, с проверкой поддержки.
- **Эскалация, а не повтор**: одинаковый эффект на 50-й раз раздражает. Усиливай по серии, ослабляй для частых микро-событий.

### Пример: пульс элемента (CSS, только transform)

```css
@keyframes pop {
  0%   { transform: scale(1); }
  35%  { transform: scale(0.94); }
  70%  { transform: scale(1.05); }
  100% { transform: scale(1); }
}
.tile--hit { animation: pop 200ms cubic-bezier(0.22, 1, 0.36, 1); }
```

## 4. Прогресс, награды и «ещё один раунд»

Визуально поддерживай желание продолжить, не манипулируя игроком:

- **Всегда виден прогресс к ближайшей цели**: полоса уровня, счётчик «до следующей награды», цель раунда. Ближайшая цель должна быть достижима за 1–3 минуты.
- **Награда ощущается**: числа, звёзды, монеты анимированы (раздел 3). Не показывай награду как сухую строку текста.
- **Экран окончания раунда — трамплин в следующий**: главная кнопка «Ещё раз»/«Дальше» крупнее и контрастнее всех остальных, находится в зоне большого пальца (нижняя треть экрана на мобильных). Вторичные действия — визуально тише.
- **Личный рекорд**: при его побитии — отдельный заметный эффект и метка «Новый рекорд!». Если рекорд не побит — показывай разницу с ним («−120 до рекорда»).
- **Визуальная «коллекция»** (если есть механика): неполученные награды показываются силуэтами/замками — это сильный мотиватор вернуться.
- **Серии по дням** (если есть механика) — выразительный, но не шейминговый UI: без «вы потеряли серию!» красным и грустных персонажей.
- **Не растягивай экраны между раундами**: от конца раунда до начала следующего — ≤ 2 касания.

## 5. Читаемость и UI

- **Контраст**: текст ≥ 4.5:1, интерактивные элементы и границы тайлов ≥ 3:1 относительно фона.
- **Кликабельное выглядит кликабельным**: тень/скос/обводка + явные состояния hover/active/disabled/focus. Некликабельное — плоское и приглушённое.
- **Тач-зоны ≥ 44×44 px**, расстояние между ними ≥ 8 px. Критичные элементы — не у самого края экрана (учитывай `env(safe-area-inset-*)`).
- **Информация не только цветом**: различай объекты также формой/иконкой/паттерном (дальтонизм). Проверь в симуляторе протанопии/дейтеранопии.
- **Иерархия HUD**: главное число (очки/ходы/время) — самый крупный элемент HUD; остальное мельче. Не более 3–4 постоянных элементов HUD.
- **Не прячь поле**: тени, градиенты, частицы и всплывающие числа не должны перекрывать клетки/цели, на которые игроку нужно нажимать. Частицы — `pointer-events: none`.
- **Единый набор иконок** (один стиль), единые радиусы (8–12 px карточки, 50% круглые кнопки) и толщины обводки.
- **Адаптивность**: вёрстка работает от 320 px ширины до десктопа; поле масштабируется, а не обрезается. Ориентацию не навязывай без необходимости.
- **Текст**: ≥ 16 px для основного, короткие слова, без длинных абзацев в игровом экране.

## 6. Стилизация: flat / semi-flat и дизайн-токены

Используй CSS-переменные — единые для сайта, с акцентом для каждой игры:

```css
:root {
  /* бренд igrasu.ru — не менять в рамках одной игры */
  --c-bg: #14172b;
  --c-surface: #1f2440;
  --c-text: #f4f6ff;
  --c-primary: #6c8cff;
  /* акцент конкретной игры — меняется */
  --c-accent: #ffb547;
  /* форма и глубина */
  --r-card: 12px;
  --shadow-soft: 0 6px 16px rgba(0, 0, 0, 0.18);
  --bevel: inset 0 2px 0 rgba(255, 255, 255, 0.25), inset 0 -3px 0 rgba(0, 0, 0, 0.2);
  --t-fast: 150ms;
  --t-base: 250ms;
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
}
```

(Значения цветов — пример. Если на сайте уже есть палитра — используй её, а не эту.)

- Палитра: 1 основной, 1–2 акцентных, нейтральные фон/текст. **Не более 4–5 основных цветов** на игровом экране.
- Глубина дёшево: мягкие тени (blur 4–16 px, прозрачность 10–25 %), градиенты из 2–3 цветов под 135°, bevel через `inset box-shadow`.
- Фон: статичный или с 2–3 параллакс-слоями максимум; никакого параллакса на слабых устройствах (см. раздел 8).
- Ассеты: SVG (оптимизированный, без метаданных) там, где возможно; иначе PNG/WebP со сжатием; спрайт-листы вместо россыпи файлов (< 150 KB на лист).
- **Стиль персонажей/объектов один на игру**: одинаковая толщина контура, одинаковый источник света (тень всегда с одной стороны).
- Не делай «дороже» ради «дороже»: новый декоративный слой должен либо улучшать читаемость, либо усиливать отклик.

## 7. Где можно «вау» (без нагрузки на игровой цикл)

- Обложки игр в каталоге/лендинге — заранее отрендеренная стилизованная картинка (НЕ рантайм-3D).
- Hero-секция главной страницы — допустима насыщеннее, грузится один раз.
- Экран победы/достижения — разовый эффект (конфетти, свечение), не постоянная сцена.
- Превью-обложка и первый экран игры **выглядят как сама игра** — не обещай в обложке то, чего нет в геймплее (это бьёт по удержанию сильнее, чем скучная картинка).

## 8. Производительность

### Жёсткие бюджеты
- Вес всей графики и звука одной игры ≤ 2–3 MB; критичный путь до первого интерактива ≤ 500 KB.
- TTI ≤ 2 с на среднем мобильном соединении (эмуляция «Fast 3G / Slow 4G»).
- Стабильные 60 FPS на среднем смартфоне, кадр ≤ 16 мс; просадки ниже 45 FPS — дефект.
- CLS ≈ 0 (размеры всех медиа заданы).
- Одновременно на экране: ≤ 60 частиц (≤ 30 на слабых устройствах), ≤ 3 слоёв параллакса.

### Техника
- Анимируй **только `transform` и `opacity`**. Запрещены анимации `width/height/top/left/margin` и тяжёлых `filter: blur()` на больших областях.
- `will-change` — только на элементах, которые анимируются прямо сейчас, и снимай после.
- Canvas: ограничь `devicePixelRatio` до 2; перерисовывай только изменённые области или только когда есть анимация (не гоняй `requestAnimationFrame` вхолостую на статичном экране).
- Частицы — через **пул объектов** (без `new` в цикле, без аллокаций на каждый кадр); lifetime ≤ 600 мс.
- Не используй `setInterval` для анимаций — только `requestAnimationFrame` или CSS.
- Останавливай анимации и звук при `document.hidden` (вкладка в фоне).

### Адаптивное качество (обязательно для эффектов, кроме базового фидбека)

```js
// Минимальный монитор: если средний FPS за ~1 с низкий — снижаем уровень эффектов
let tier = 2; // 2 = полный, 1 = упрощённый, 0 = минимальный
let frames = 0, last = performance.now();
function qualityTick(now) {
  frames++;
  if (now - last >= 1000) {
    const fps = frames * 1000 / (now - last);
    if (fps < 45 && tier > 0) tier--;
    frames = 0; last = now;
  }
  requestAnimationFrame(qualityTick);
}
requestAnimationFrame(qualityTick);
// tier 2: частицы + параллакс; tier 1: меньше частиц, без параллакса; tier 0: только scale/opacity фидбек
```

Базовый отклик на клик (раздел 3, первая строка) **никогда** не отключается, даже на tier 0 — он дешёвый и критичный.

## 9. Доступность и настройки пользователя

- Учитывай `prefers-reduced-motion`: убирай тряску, параллакс, крупные вспышки; оставляй мягкий fade и изменение цвета.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 1ms !important; transition-duration: 1ms !important; }
}
```
- Не используй мигание чаще 3 раз в секунду на большой площади (риск светочувствительной эпилепсии). Конфетти и вспышки — короткие и без стробоскопа.
- Звук и вибрация отключаются; выбор запоминается.
- Фокус с клавиатуры виден (outline), игровые действия доступны не только мышью, где механика это позволяет.

## 10. Реклама и графика

- Рекламные блоки визуально **отделены** от игрового поля и не похожи на игровые кнопки; зазор между игровыми кнопками и рекламой ≥ 16 px.
- Игровые экраны не должны «прыгать» при загрузке рекламы (резервируй место).
- Не размещай крупную «главную» кнопку рядом с рекламой так, чтобы случайный клик по рекламе был вероятнее намеренного.
- Награды за просмотр рекламы (если есть) показывай честно: что получит игрок, отдельной кнопкой, без визуального давления.

## 11. Проверка и чек-лист (для ИИ-агента)

### Как проверять (измеримо)
- Вес: подсчитай суммарный размер новых/изменённых ассетов (`du`, сборка), сравни с базой.
- Скорость: Lighthouse/DevTools с троттлингом (Slow 4G, CPU ×4); зафиксируй TTI/LCP/CLS до и после.
- FPS: запись Performance профиля в DevTools на CPU ×4 во время самого «тяжёлого» момента (серия комбо, победа).
- Автопроверка, если есть Playwright/Puppeteer: запустить игру в эмуляции мобильного, сделать сценарий «первый ход → серия → победа», убедиться в отсутствии ошибок консоли и сдвигов вёрстки.
- Контраст: проверь основные пары цветов по WCAG.

### Чек-лист
- [ ] Не добавлен WebGL/3D-рендер в игровой цикл простой игры.
- [ ] Суммарный вес новых ассетов в бюджете (раздел 8), критичный путь ≤ 500 KB.
- [ ] Все новые анимации идут через `transform`/`opacity`, нет reflow.
- [ ] Первые 10 секунд: поле видно сразу, первое действие подсвечено, первый успех быстро (раздел 2).
- [ ] Для каждого ключевого события есть отклик (таблица раздела 3); клик отвечает ≤ 100 мс.
- [ ] Анимации в игровом цикле ≤ 400 мс, экраны наград пропускаются тапом.
- [ ] Виден прогресс к ближайшей цели; кнопка «Ещё раз/Дальше» главная и в зоне большого пальца.
- [ ] Контраст проверен (текст ≥ 4.5:1, интерактив ≥ 3:1); тач-зоны ≥ 44×44 px.
- [ ] Информация не передаётся только цветом.
- [ ] Палитра и радиусы совпадают с общим стилем сайта; ≤ 4–5 основных цветов на экране.
- [ ] Эффекты не перекрывают игровое поле; частицы `pointer-events: none`.
- [ ] Есть адаптивное качество; на tier 0 базовый отклик сохранён.
- [ ] Учтены `prefers-reduced-motion`, отключение звука; нет стробоскопа.
- [ ] Реклама не маскируется под игру, нет сдвигов вёрстки (CLS ≈ 0).
- [ ] Загрузка протестирована на эмуляции слабого устройства/сети; нет ошибок в консоли.
- [ ] SVG оптимизированы, PNG/WebP сжаты, спрайты собраны в листы.
- [ ] Коммит описан по шаблону ниже.

## 12. Чего не делать (антипаттерны)

- Не «улучшать» графику, добавляя большие фоновые видео, тяжёлые blur-фильтры, многослойные тени на сотнях элементов.
- Не менять игровую логику и баланс под видом графики.
- Не делать эффекты, которые нельзя пропустить, и экраны, которые нельзя закрыть.
- Не прятать кнопку выхода/паузы и не делать её неотличимой от рекламы.
- Не смешивать стили иконок и арта в одной игре.
- Не добавлять эффекты «на всякий случай» без события из карты раздела 3.
- Не ломать то, что уже работает: если у игры есть узнаваемый стиль, усиливай его, а не заменяй.

## 13. Итоговое правило приоритета

Сначала **ясность и отклик**, затем **ощущение прогресса**, затем **стиль**, и только потом **детализация**. Качество восприятия казуальной игры строится на скорости, понятности и приятной отдаче на каждое действие — именно это заставляет игрока сыграть ещё раунд.
