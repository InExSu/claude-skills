# State Machine and SRP — когда использовать switch машину состояний Шалыто

## Правило выбора

Перед тем как писать switch машину состояний Шалыто, проверь: есть ли хотя бы один из признаков
сложности. Если нет — пиши обычный код с SRP.

---

## Когда switch машина состояний Шалыто оправдана

Используй switch машину состояний Шалыто если есть **хотя бы один** из признаков:

- **Нелинейные переходы** — из одного состояния можно попасть в разные
  следующие в зависимости от условий
- **Повторные входы** — состояние может быть достигнуто из нескольких других
  состояний
- **Пропускаемые состояния** — часть состояний выполняется не всегда
- **Цикл обработки с условным продолжением** — например, постраничная
  загрузка, retry-логика, обход дерева
- **Явная конечность** — логика моделирует протокол, парсер, воркер с
  жизненным циклом

### Пример — оправданная switch машина состояний Шалыто

```php
// Постраничная загрузка: fetch → check → fetch или finish
case 'fetch_Page':
    $result = API_Fetch($ns, $page);
    $state  = $result['has_More'] ? 'fetch_Page' : 'data_Process';
    break;
```

---

## switch или match

Внутри машины состояний можно использовать как `switch`, так и `match` — выбирать тот, который нагляднее.

Использовать **`match`** если:
- Каждое состояние возвращает значение (новое состояние, результат)
- Тело каждой ветки — одно выражение
- Важна строгая проверка без неявного приведения типов

```php
// match нагляднее когда состояние — это просто переход
$state = match ($state) {
    'fetch_Page'   => $result['has_More'] ? 'fetch_Page' : 'data_Process',
    'data_Process' => 'finish',
    default        => throw new \UnexpectedValueException("Unknown state: $state"),
};
```

Использовать **`switch`** если:
- Тело состояния — несколько операторов
- Внутри состояния есть побочные эффекты (вызовы функций, присваивания)
- Нужен `break 2` для выхода из цикла

```php
// switch нагляднее когда в состоянии есть логика
case 'fetch_Page':
    $result = API_Fetch($ns, $page);
    $ns->data[] = $result['items'];
    $state = $result['has_More'] ? 'fetch_Page' : 'data_Process';
    break;
```

## Когда switch машина состояний Шалыто вредна — использовать обычный код

Если переходы **строго линейные** и каждое состояние выполняется **ровно
один раз** — switch машина состояний Шалыто только добавляет шум. Писать обычный код.

Признаки ложной switch машины состояний Шалыто:
- Все переходы вида `$state = 'next_State'` без условий
- `case 'finish': break 2` в конце
- `// no break — fall through` как способ перейти к следующему шагу
- Состояния можно заменить на последовательные вызовы функций

### Пример — ложная switch машина состояний Шалыто → обычный код

```php
// Было: три состояния, каждое ровно один раз, переходы линейные
case 'file_Prepare': ... $state = 'data_Filter'; break;
case 'data_Filter':  ... $state = 'file_Write';  break;
case 'file_Write':   ... $state = 'finish';      break;

// Стало: просто три вызова
$logDir    = Log_Dir_Prepare();
$foundRows = KPP_Rows_Filter($ns);
$lines     = KPP_Log_Lines_Build($foundRows);
```

## SRP при отказе от switch машины состояний Шалыто

Когда switch машина состояний Шалыто не нужна — каждый смысловой блок выносить в функцию.

Правила:
- Функция делает **одно** — фильтрует, строит, записывает
- Имя функции **называет действие**: `Rows_Filter`, `Log_Lines_Build`,
  `Dir_Prepare`
- Верхний уровень читается как **план**: подготовить → обработать → записать
- Цикл выносить в функцию если у него есть **название** (самостоятельная
  логика). Не выносить если цикл простой и контекст важен

### Структура верхнего уровня

```php
function v_KPP_Logs_RWD(NS_Container $ns): void
{
    Log_Dir_Prepare();                            // подготовить
    $foundRows = KPP_Rows_Filter($ns);            // обработать
    $lines     = KPP_Log_Lines_Build($foundRows); // собрать
    Log_File_Write($filePath, $lines);            // записать
}
```

- [ ] Есть нелинейные переходы?
