# Явная семантика кодов возврата: 0 и 1 не гадают

## Проблема

В C-подобных конвенциях (bash, POSIX) код возврата читается двумя противоположными
способами, и оба законны:

- **предикат** — `0` = «да», `1` = «нет» (`if f_Is_Valid; then` — идиома bash);
- **статус выхода** — `0` = «успех», не-ноль = «ошибка» (`exit`, `run_step`).

Пока функция одна, путаницы нет. Она появляется, когда одна функция встречает
**двух читателей с противоположным ожиданием**, а смысл цифры держится в голове
автора. Реальный случай (гейт «секретов в отслеживаемых нет», 22.10.2026):

```bash
# Определение: 0 = «имя секретное» (предикат «да»)
f_Path_Hidden() {
    case "$1" in
        creds.php|*/creds.php) return 0 ;;   # секретное → 0
        scripts/_tmp/*)        return 0 ;;
        *)                     return 1 ;;
    esac
}

# Читатель 1 (сканер): 0 = «НАЙДЕННАЯ НАХОДКА» — красим
if f_Path_Hidden "$f"; then f_Hit "$f"; fi

# Читатель 2 (guard): 0 = «ПРОПУСТИТЬ» — не красим
case "$f" in) esac   # тот же смысл 0, противоположное действие
```

Легальный файл `scripts/_tmp/.gitkeep` отличался от запрещённых соседей только
тем, что функция возвращала для него `1` в одной ветке и `0` в пяти. Регрессия
диагностировалась только трассировкой `bash -x`: ни имя функции, ни вызов не
говорили, что значит возвращённая цифра.

## Правила

1. **Предикат именуется вопросом.** Имя функции отвечает на да/нет-вопрос
   (`f_Path_Is_Secret`, `f_Has_Token`, `f_File_Is_Tracked`), возвращает `0` = «да»,
   и используется ТОЛЬКО как условие: `if f_Path_Is_Secret "$f"; then …`.
2. **Статус не смешивается с предикатом.** Если функция возвращает код статуса
   (нашла/не нашла, зелёный/красный, «есть находки»), она не вызывается в `if`
   молча: у вызова — обёртка-предикат с явным именем или комментарий
   `# 0 = <слово>`. Слова важнее числа.
3. **Два читателя одного кода — красный флаг.** Если один и тот же `return 0`
   один вызов трактует как «найдено», а другой как «пропустить» — это не две
   трактовки, это болезнь: у кода нет имени. Свести к одному решателю: либо
   два предиката с разными именами, либо возвращение СЛОВА
   (`echo hit|skip` + сравнение со словом), либо именованные константы.
4. **Исключения-ветки не шифруются цифрой.** Легальное исключение внутри
   «запрещающего» предиката (`creds.php.dist` рядом с `creds.php`,
   `.gitkeep` рядом со scratch-дампами) оформляется отдельной веткой case с
   комментарием «почему легально», а не подгонкой `return 0/1` под нужный
   ответ читателя.

## Было → стало

**Было (❌):** смысл кода держится в голове.

```bash
f_Path_Hidden() { case "$1" in creds.php) return 0 ;; *) return 1 ;; esac; }
if f_Path_Hidden "$f"; then f_Hit "$f"; fi    # 0 = секретное? найдено? что?
```

**Стало (✅):** смысл назван дважды — в имени и у вызова.

```bash
# Предикат: 0 = «путь с секретным именем» (правило guard'а, имя целиком).
f_Path_Is_Secret() {
    case "$1" in
        creds.php|*/creds.php) return 0 ;;
        scripts/_tmp/.gitkeep) return 1 ;;  # держатель каталога легален (gitignore белеит его)
        scripts/_tmp|scripts/_tmp/*) return 0 ;;
        *) return 1 ;;
    esac
}

# Сканер: находка = секретное имя среди отслеживаемых (0 = да, красим).
if f_Path_Is_Secret "$f"; then f_Hit 'ПУТЬ' "$f"; fi
```

## Чек-лист ревью

- [ ] Имя функции-предиката — да/нет-вопрос, а не глагол действия?
- [ ] У каждого вызова в `if` понятно без чтения определения, что значит код?
- [ ] Нет ли второго читателя того же `return 0` с противоположным действием?
- [ ] Исключающая ветка объяснена комментарием «почему легально»?
- [ ] Новое правило не продублировано вторым комментарием в другом файле?

## Границы

- Коды выхода самого скрипта (`exit 0/1/2`) — не здесь: их семантику задаёт
  вызывающий (оркестратор/CI), и она уже документирована в шапке скрипта.
  Правило — о ФУНКЦИЯХ, чей код возврата читается внутри одного файла или
  библиотеки.
- В языках с настоящим `bool` (`true`/`false`) проблема слабее, но правило
  «имя — вопрос, у неочевидного вызова — слова» остаётся: `parseInt` в JS
  возвращает `NaN`, а не булево — смешение типов и есть тот же антипаттерн.
