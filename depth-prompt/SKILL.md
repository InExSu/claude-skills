# Depth Prompt

Просить не просто выполнить задачу, а сделать её максимально качественно — сдвинуть планку, на которой агент останавливается.

## Правило

Добавлять к запросу требование глубины **и** назвать, что именно значит «хорошо» здесь.

«Сделай настолько хорошо, насколько возможно» работает, потому что меняет критерий остановки: агент перестаёт спрашивать «работает ли» и начинает спрашивать «что сломает это первым».

## Почему одной фразы мало

Без расшифровки «хорошо» агент угадывает, и угадывает по-разному: один добавит обработку ошибок, другой — комментарии, третий — переусложнит архитектуру. Поэтому к фразе прикладывайте 2–3 конкретных измерения:

| Что значит «глубоко» | Когда это главное |
|---|---|
| Крайние случаи: пусто, один элемент, дубли, юникод, переполнение | парсеры, конвертеры, импорт данных |
| Ошибки: что при сбое сети, таймауте, 429, невалидном ответе | всё, что ходит во внешний мир |
| Надёжность при повторе: идемпотентность, блокировки | cron, миграции, запись в чужие данные |
| Понятность: следующий читатель разберётся без автора | библиотечный код, публичные API |
| Проверяемость: тесты на поведение, а не на покрытие | любая логика с ветвлениями |

## Примеры

### Парсер

❌ «Напиши функцию парсинга CSV.»
✅ «Напиши функцию парсинга CSV и сделай это настолько хорошо, насколько возможно: битый ввод, пустые строки, юникод, огромный файл, сохранение исходных данных при ошибке. Плюс тесты на каждый случай.»

### Запись в чужие данные

❌ «Напиши скрипт, который обновит статусы в CRM.»
✅ «Напиши скрипт обновления статусов и сделай настолько хорошо, насколько возможно: dry-run по умолчанию, предохранитель на объём, идемпотентность при повторном запуске, откат при расхождении, лог каждого изменения.»

### Функция с ветвлениями

❌ «Напиши расчёт скидки.»
✅ «Напиши расчёт скидки максимально качественно: границы диапазонов, отрицательные значения, округление денег, отсутствие скидки, тесты на каждую границу.»

## Когда не применять

- **Черновик или спайк.** Цель — проверить идею за час; глубина тут вредит, потому что съедает время на то, что будет выброшено.
- **Одноразовый скрипт.** Если он проживёт один запуск, обработка всех крайних случаев — работа в пустоту.
- **Нет доступа к проверке.** Просить глубину там, где нельзя запустить и посмотреть результат, — значит получить правдоподобный текст вместо проверенного кода.

## Антипаттерны

- **«Сделай идеально» без критерия.** Агент имитирует глубину: больше комментариев, больше абстракций, тот же набор необработанных случаев.
- **Глубина без границ.** «Учти все случаи» → бесконечная работа. Называйте, где заканчивается «всё».
- **Глубина вместо ясности.** Если требование непонятно, глубина сделает непонятное более подробным, а не более верным.
- **Требование глубины на каждом запросе.** Привычка обесценивает фразу: она перестаёт быть сигналом.

## Чек-лист

- [ ] Запрос содержит требование к качеству, а не только к результату.
- [ ] Названы 2–3 измерения, что значит «хорошо» именно здесь.
- [ ] Агент проверяет граничные случаи и ошибки, а не только счастливый путь.
- [ ] Добавлены тесты или проверки на эти случаи.
- [ ] Задача действительно стоит глубины (не черновик).
