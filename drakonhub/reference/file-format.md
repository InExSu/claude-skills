# Формат файлов DrakonHub: `.drakon` и `.graf`

Глубокое погружение для скилла `drakonhub`.
Краткая версия — в [SKILL.md](../SKILL.md).
Факты сверены с `drakon_examples` настоящего редактора и его исходниками
(`dh2core.js`, `drakon_canvas.js`).

## 1. Корень `.drakon`

```json
{"type": "drakon", "items": {"<id>": {...}}, "style": ""}
```

- `type` — всегда `"drakon"`.
- `name` — заголовок диаграммы (нативное поле редактора; дублируется
  в `header.content`). Сериализатор читает `name`, иначе `header.content`.
- `items` — словарь «id → иконка». Id — строки (в нативных файлах числа).
- `style` — строка с JSON-объектом стилей или `""`. Если непустая —
  обязана парситься как JSON-объект.
- У иконок поле `style` опционально; правило то же.

## 2. Иконки потока

### `action` — шаг

```json
"10": {"type": "action", "content": "Размяться", "one": "20", "side": "15"}
```

- `content` — текст, императив, один шаг.
- `one` — следующий узел. Обязателен.
- `side` — опциональная ссылка на `duration`.

### `question` — вопрос

```json
"50": {"type": "question", "flag1": 1, "content": "Устал?",
       "one": "60", "two": "70"}
```

- `one` и `two` обязательны.
- `flag1 = 1` → `one` = ветка «да», `two` = ветка «нет».
  `flag1 = 0` — наоборот. Главная (идущая вниз) ветка — `one`.
- Вопрос атомарный: без *и* / *или* / отрицания (`check` — замечание).

### `select` / `case` — выбор

```json
"4": {"type": "select", "content": "Сколько?", "one": "5"},
"5": {"type": "case", "content": "0 - 250", "one": "27", "two": "8"},
"8": {"type": "case", "content": "", "one": "30"}
```

- `select.one` — первый `case` (иначе ошибка).
- `case.one` — тело варианта; `case.two` — следующий `case`.
- У последнего `case` поля `two` нет. Пустой `content` — вариант по умолчанию.

### `branch` — ветка силуэта

```json
"4": {"type": "branch", "branchId": 0, "content": "Оформить", "one": "10"}
```

- `branchId` — целое число, уникален.
- `branchId: 0` — главная (левая) ветка. В простом файле ветка одна.
- Нативный редактор в силуэтах нумерует с 1 без нулевой ветки —
  `check` принимает, но выдаёт замечание; генератор пишет `0..N-1`.
- `content` опционален (у главной ветки простой схемы его обычно нет).
- Ветка — легальная цель прыжка (рестарт ветки): см. §5.

### `loopbegin` / `loopend` — скобки цикла

```json
"20": {"type": "loopbegin", "content": "Повторить 10 раз", "one": "30"},
"60": {"type": "loopend", "one": "1"}
```

- Тело — между ними по потоку. `loopend.one` — продолжение после цикла.
- `content` у `loopend` обычно пуст.

### `arrow-loop` — явный переход

```json
"70": {"type": "arrow-loop", "one": "20"}
```

- Линия без текста (`content` обязан быть пустым).
- Обычное применение — ребро назад (возврат к началу цикла).

### `insertion` / `address` — вставка и адрес

Как `action` (`content` + `one`). В примерах не встречаются,
поддерживаются для совместимости. В DSL — маркеры `+` и `&`.

### `simpleinput` / `simpleoutput` (а также `input`, `output`)

Иконки ввода/вывода редактора (`content` + `one`). В DSL — `<<` и `>>`.
`shelf` / `process` принимаются проверкой, в DSL каноникализуются
в действия.

## 3. Внепотоковые иконки

### `comment` — комментарий

```json
"91": {"type": "comment", "content": "Открытый список пуст", "one": "88"}
```

- `one` — узел, к которому относится (или следующий комментарий в цепочке).
- В анализе потока **прозрачен**: достижимость и пути в `end` идут сквозь него.
- Ничего не обязано на него указывать; висячий комментарий легален.

### `duration` — длительность

```json
"15": {"type": "duration", "content": "20 мин"}
```

- Только `content`. Связей нет.
- Обязан быть привязан ровно к одному `action.side` (иначе ошибка).

### `callout` — выноска

```json
"55": {"type": "callout", "left": 150, "top": -20, "width": 160,
       "height": 40, "content": "примечание", "px": -60, "py": 20, "zIndex": 1}
```

- Свободные координаты, связей нет. Все числовые поля обязательны.

### `header` / `end`

```json
"2": {"type": "header", "content": "Приём заказа"},
"1": {"type": "end"}
```

- Ровно один `header` и ровно один `end` на файл.
- Заголовок диаграммы — `header.content` (так пишет сам редактор:
  `header.content = model.doc.name`).
- Связей нет.

## 4. Инварианты (проверяет `check`)

1. Все ссылки (`one`/`two`/`side`) указывают на существующие узлы.
2. `select.one` → `case`; `case.two` → `case`.
3. Каждый узел потока достижим хотя бы из одной ветки.
4. Из каждого узла потока есть путь в `end` (сквозь комментарии).
5. Циклы — только явные (§5).
6. `duration` привязан к `action.side`; `arrow-loop` без текста.

Нарушение 1–2, 6 — ошибка структуры; 3–5 — ошибка потока.
Языковые замечания (не ошибки): вопрос с *и*/*или*/отрицанием,
действие со знаком препинания в конце.

## 5. Какие циклы легальны

Цикл обязан закрываться одним из способов:

- через `arrow-loop` (классическое ребро назад);
- через `loopbegin`/`loopend` (скобки цикла, возврат визуальный);
- прыжком на узел `branch` (рестарт ветки — идиома «Work out», «Lunch break»).

Всё остальное — goto-спагетти, `check` отклоняет с путём цикла.

## 6. Round-trip и каноническая форма

`roundtrip` делает `.drakon → DSL → .drakon → DSL` и сравнивает два DSL-текста.
Нормализация (одинакова в обе стороны, поэтому сравнение честно):

- повторно встречаемые узлы не дублируются (первое вхождение побеждает);
- цепочки комментариев сворачиваются к виду «все висят на целевом узле»;
- порядок веток верхнего уровня — порядок обхода (источники первыми);
- `flag1 = 0` переписывается в каноническое `да → one, нет → two`
  (граф с yes/no-метками тот же);
- стили, координаты выносок и id в DSL не входят.

## 7. DSL: точные правила

- Отступ — пробелы (таб = 4 пробела). Пустые строки пропускаются.
- `#` — только первая непустая строка (заголовок → `header.content`).
- `да:` / `нет:` (или `yes:` / `no:`) — только дети `?`; текст после
  двоеточия запрещён, тело — более глубокие строки.
- `=` — только дети `$`.
- `%` — только дети действия (создаёт `duration` + `action.side`).
- `^` без детей: `one` = следующий сосед, иначе продолжение блока;
  внутри `~`, если целью выходит `loopend`, — возврат к `loopbegin`.
- `^` с детьми внутри `~`: дети — путь возврата, конец пути — `loopbegin`.
- `@` на верхнем уровне: либо все конструктивные строки — ветки,
  либо веток нет вообще (одна неявная ветка 0).
- Экранирование контента: `\n` → перевод строки, `\\` → слэш,
  ведущий символ маркера — обратным слэшем (`\? Что?` как действие).
- Строка ровно `да:` / `нет:` зарезервирована (не может быть действием).

## 8. Формат `.graf` (ментальные карты)

```json
{"type": "graf", "items": {"1": {"type": "idea", "content": "Тестирование",
  "parent": "root", "treeType": "treeview", "ordinal": 0}}, "style": ""}
```

- Тип узла: `idea`, `ridea`, `conclusion`.
- `parent` — id родителя или `"root"`. Циклы запрещены (`check` ловит).
- `ordinal` — порядок среди соседей.
- `read` печатает карту планом с дефисами по глубине.
- Пример: [templates/mind-map.graf](../templates/mind-map.graf).

## 9. Раскладка рендера

Сетка «ветка = столбец»: главная ветка слева, ответвления вопросов
и варианты выбора — вправо (резерв колонки = глубина вложенности).
Вопрос `one` идёт вниз, `two` — вправо-вниз. Петли назад — красной
пунктирной линией. Вывод `svg` — картинка, `map` — координаты иконок.

## 10. Mermaid (`.mmd`)

`drakon_render.py mermaid` печатает `flowchart TD` — ту же диаграмму
для просмотра в Markdown/GitHub, без DrakonHub:

| ДРАКОН | Mermaid |
|---|---|
| `action` | `id["текст"]` |
| `question` | `id{"текст"}`, рёбра `-- Да -->` / `-- Нет -->` |
| `select` / `case` | ромб `id{"..."}` и ветки `= подпись` |
| `loopbegin` / `loopend` | стадион `id(["~ ..."])` / `id(["~ /цикл"])` |
| `simpleinput` / `output` | `id[/"..."​/]` / `id[\"..."\]` |
| `end` | `id(["КОНЕЦ"])` |

- `header` → узел `HEADER`, `comment` / `callout` / `duration` не входят
  в поток и пропускаются (комментарии прозрачны: ребро идёт к их цели);
- идентификаторы узлов — `n<id>`, стабильны между прогонами;
- `flag1` определяет, какая ветка `question` подписана «Да»;
- вывод проверяется `mmdc` (mermaid-cli) и рендерится на GitHub.
