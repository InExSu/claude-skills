# DrakonHub — создание и чтение DRAKON-диаграмм

## Когда применять

Пользователь просит нарисовать/описать алгоритм, бизнес-процесс, медпротокол, инструкцию
в нотации DRAKON; открыть/проверить/поправить файл `.drakon` или `.graf`; перенести
существующую блок-схему или текст в DrakonHub.

Суть работы: **обычный, человеческий текст → файл JSON с диаграммой ДРАКОН.** Посмотреть
готовый файл можно на [drakonhub.com](https://drakonhub.com/) — веб-редакторе DrakonHub
Степана Митькина, — либо локально, без редактора: `scripts/drakon_render.py svg` (раздел 7).

## 1. Правила языка DRAKON (обязательны)

1. **Начало — слева сверху.** Заголовок (имя диаграммы) — левый верхний угол.
2. **Поток сверху вниз.** Стрелок нет: порядок задаётся положением.
3. **Ветвление — только вправо.** Никогда влево.
4. **Линии не пересекаются.**
5. **«Чем правее, тем хуже».** Самый успешный/частый путь идёт прямо вниз; отклонения и
   ошибки уходят вправо. Последняя правая ветка — наихудший исход.
6. **Один вход, один выход.** Ровно один `end`. Не заменять конец ссылкой на другой процесс.
7. **Одна иконка = один шаг.** Действие ИЛИ вопрос, не оба сразу.
   Не «Открыть форму и ввести данные», а два действия.
8. **Действие — команда в императиве**: «Сохранить заказ в БД», а не «База данных».
9. **Вопрос без «не», «и», «или».**
   - вместо «не» — поменять Да/Нет местами (`flag1`);
   - вместо «и»/«или» — разбить на два `question`.
10. **Силуэт** (`branch`) — делит длинный алгоритм на именованные части слева направо.
    Если в одной вертикали больше ~15 иконок — делай силуэт.
11. **Вызов другой диаграммы — `insertion`**, а не `action`.
12. Порядок кейсов в `select`: самый вероятный слева, «остальные случаи» — крайний правый
    `case` с пустым `content`.

## 2. Формат файла `.drakon`

Обычный JSON (UTF-8). Верхний уровень:

```json
{
  "name": "Обработка заказа",          // имя диаграммы (дублирует заголовок на холсте)
  "type": "drakon",                    // "drakon" | "graf" | "free" | "basic"
  "params": "<p>Условие старта: клиент оформил заказ</p>",  // формальные параметры, строка
  "description": "Ресурсы: CRM, склад",// описание
  "style": "{\"iconBack\":\"#ffffff\"}", // JSON-строка, не объект
  "items": { "header": {...}, "1": {...} }
}
```

- `items` — объект `id -> item`; **ключи всегда строки** (`"1"`, `"header"`), id произвольные,
  но уникальные. Два зарезервированных id: `header` и `params`.
- Поля item: `type`, `content` (строка, может быть HTML: `<p>...</p>`, `<strong>`, переносы `\n`),
  `one`, `two`, `side`, `flag1`, `branchId`, `style` (JSON-строка), `secondary`, `link`.
- Устаревшее поле `text` — синоним `content` (при импорте `text` превращается в `content`).
  Для новых файлов пиши `content`.
- `style` у diagram и у item — **строка с JSON**, а не вложенный объект.

Подробности и крайние случаи: `reference/file-format.md`.

## 3. Иконки: `type` → назначение → связи

| type | Что это | Ключевые поля |
|---|---|---|
| `header` | Заголовок. id строго `"header"`. Текст берётся из `name` | `style` |
| `params` | Формальные параметры (триггер, акторы). id строго `"params"` | `content` |
| `branch` | Ветка силуэта | `branchId` (порядок слева направо, 0..n), `content` (имя ветки), `one` → первая иконка ветки |
| `action` | Действие | `content`, `one` |
| `question` | Вопрос Да/Нет | `content`, `one` (вниз), `two` (вправо), `flag1` |
| `select` | Выбор (множественный) | `content` (что выбираем), `one` → первый `case` |
| `case` | Вариант выбора | `content`, `one` → тело варианта, `two` → следующий `case` |
| `loopbegin` | Начало цикла | `content` («Повторить 10 раз», «Пока есть задачи»), `one` → первая иконка тела |
| `loopend` | Конец цикла | `one` → иконка **после** цикла |
| `arrow-loop` | Петля-стрелка (цикл «назад» без пары begin/end) | `one` |
| `insertion` | Вставка: вызов другой диаграммы, родитель ждёт | `content`, `one` |
| `end` | Конец (ровно один) | — |
| `comment` | Комментарий справа от иконки | `content`, `one` |
| `duration` | Длительность действия. Привязывается полем `side` у `action` | `content` («20 мин») |
| `pause`, `timer`, `ctrlstart`, `ctrlend` | Пауза, таймер, начало/конец контрольного периода | `content`, `one` |
| `simpleinput` / `simpleoutput` | Простой ввод/вывод: ожидание события, ожидание параллельного процесса | `content`, `one` |
| `process`, `shelf`, `input`, `output`, `address` | Расширенные (параллельный процесс, полка, ввод-вывод, переход) | `content`, `one` |
| `parbegin` / `parend` | Блок «Одновременная работа» (продвинутый уровень) | см. ниже |
| `callout` и прочие «свободные» | Плашка/картинка, не в потоке | `left`,`top`,`width`,`height`,`px`,`py`,`zIndex`,`content`,`style` |

**В файле НЕТ типа `foreach`.** Кнопка «FOR Loop» в UI создаёт пару `loopbegin` + `loopend`.

### Семантика связей

- `one` — продолжение вниз по «вертелу» (прямой путь).
- `two` — правая ветка.
- `question`: `flag1: 1` (по умолчанию) → `one` = **Да**, `two` = **Нет**.
  `flag1: 0` → наоборот: `one` = Нет, `two` = Да. Меняй `flag1`, чтобы «Да» шёл прямо вниз.
- `select` → цепочка `case` через `two`: `select.one` = первый case, `case.two` = следующий case,
  у последнего `case` поле `two` отсутствует. `case.one` = первая иконка тела варианта.
- `loopbegin` → тело → `loopend`; выход из цикла — `loopend.one`.
- `side` у `action` = id иконки `duration` (длительность действия).
- Старт диаграммы — `branch` с минимальным `branchId` (обычно 0).

### Блок «Одновременная работа» (продвинутый)

```
parend  { "one": "<иконка после блока>" }
parbegin_1 { "one": "<id parend>", "two": "<id parbegin_2>" }
parbegin_2 { "one": "<id parend>", "two": "<первая иконка тела потока>" }
```
Дальше потоки добавляются по цепочке `two`. Если число параллельных потоков заранее
неизвестно — используй `process` (параллельный процесс) + `simpleinput` (ожидание).
Для последовательного вызова подпроцесса — `insertion`.

## 4. Как создать диаграмму

1. **Имя** = цель процесса, кратко и конкретно («Регистрация нового клиента», не «Процесс»).
2. **`params`** = условие старта + акторы + ресурсы.
3. Выпиши шаги: действие или вопрос, по одному на иконку.
4. Если ветка длинная — силуэт: именованные части слева направо.
5. Собери JSON: `header`, один или несколько `branch`, цепочки иконок, один `end`.
6. Проверь: `python3 scripts/drakon_tool.py check file.drakon`.
7. Открой в DrakonHub (Import/Open) — редактор сам раскладывает координаты,
   вручную `left/top` считать не нужно (нужны только для свободных элементов).

Минимум жизнеспособного файла:

```json
{
  "name": "Покормить кота",
  "type": "drakon",
  "params": "<p>Условие старта: кот пришёл и требует еду</p>",
  "items": {
    "header": { "type": "header" },
    "b0": { "type": "branch", "branchId": 0, "content": "Кормление", "one": "1" },
    "1": { "type": "action", "content": "Насыпать корм в миску", "one": "2" },
    "2": { "type": "action", "content": "Налить воды", "one": "3" },
    "3": { "type": "end" }
  }
}
```

Готовые шаблоны: `templates/minimal.drakon`, `templates/silhouette.drakon`,
`templates/choice-and-loop.drakon`.

## 5. Как прочитать существующую диаграмму

```bash
python3 scripts/drakon_tool.py read  path/to/file.drakon   # псевдокод по ветвям
python3 scripts/drakon_tool.py check path/to/file.drakon   # отчёт об ошибках
```
Скрипт поддерживает `.drakon` и `.graf` (ментальные карты: `ridea`/`idea`, поля
`parent`, `ordinal`, `treeType`).

### Быстрая проверка «откроется ли DrakonHub»

Чекер ловит только топологические ловушки (возвраты назад по ветке, лишние
`loopend`, пустые `content`). Чтобы убедиться, что движок раскладки
**реально** строит холст без зависания, подними `drakonhub_desktop/drakonhub.html`
локально (это полностью браузерный билд, без Tauri) и открой файл через
`Import` → скрытый `<input type="file">`:

```bash
# 1. локальный сервер
python3 -m http.server 8765 --bind 127.0.0.1   # из корня drakonhub_desktop

# 2. headless-браузер (chromium уже в кэше Playwright)
agent-browser open  http://127.0.0.1:8765/drakonhub.html
agent-browser find text Import click
agent-browser upload 'input[type=file]' /path/to/your.drakon
agent-browser screenshot  /tmp/dh.png
```

Если в консоли (`agent-browser errors`) чисто и силуэт появился — диаграмма
безопасна для редактора.

### 5.1 Надёжная проверка: `scripts/drakon_try.py render`

Браузерный путь (UI + Import) часто недоступен: на drakonhub.com страница
входа, а `agent-browser` может отсутствовать. Надёжнее прогнать **настоящий
движок DrakonHub** (`drakon_canvas.js`) без UI:

```bash
python3 scripts/drakon_try.py render path/to/file.drakon   # OK / HANG / ERROR
python3 scripts/drakon_try.py path/to/file.drakon          # то же (render по умолчанию)
python3 scripts/drakon_try.py stack path/to/file.drakon    # стек зависания (CDP Debugger.pause)
```

Скрипт сам клонирует `stepan-mitkin/drakonhub_desktop` в кэш, поднимает
`http.server` и открывает страницу в headless-chromium из кэша Playwright.
Результаты:

| Результат | Что значит | Что делать |
|---|---|---|
| `OK` | холст построен (печатается число узлов) | файл безопасен |
| `HANG` | `layoutSilhouette`/`findLeftLinks` ушли в бесконечный обход | перестроить по § 8.1 |
| `ERROR ... getDown/getUp/tail/type` | скевер ветки оборван | см. § 8.1, правило 2 |
| `ERROR ... head.right is busy` | в узел ведёт два `two` | см. § 8.1, правило 1 |

Движок можно дергать и напрямую из браузера — см. § 5.2.

### 5.2 Прямой вызов движка из headless-браузера

`drakonhub.html` — полностью браузерный билд. Зависимости модуля
`drakon_canvas` надо связать вручную (так делает `local.js`):

```js
const dc = window.drakon_canvas();
const _common = window.dh2common(), _utils = window.utils(), _html = window.html_0_1();
const _core = window.dh2core();
_core.dh2common = _common; _core.html = _html; _core.utils = _utils;
dc.edit_tools = window.edit_tools(); dc.html = _html;
dc.tracing = _core;                       // НЕ window.drcore - его нет в глобалах
dc.utils = _utils; dc.gconfig = window.dh2config();
const w = dc.DrakonCanvas(); w.init();
holder.appendChild(w.render(1200, 800, {}));
await w.setDiagram('t1', diagram, undefined, true);   // здесь может зависнуть
```

`window.drcore` не определён (только `dh2core`), `dh2common` — фабрика
(`window.dh2common()`), `drakon_canvas.DrakonCanvas` доступен только после
`window.drakon_canvas()`.

Чтобы увидеть, где именно висит, ставьте точкой останова `Debugger.pause`
через CDP и читайте `callFrames` — так находится конкретная функция
(`findLeftLinks`, `getDown`, `createEdge`).

## 6. DSL — компактный текст вместо JSON

LLM плохо пишет `.drakon` руками: надо самому придумывать id и связывать
`one/two/side`. Поэтому есть текстовый DSL — конвертер сам распределяет id,
строит связи и силуэт. Агент пишет алгоритм текстом с отступами, конвертер
выдаёт валидный `.drakon`.

Скрипт: `scripts/drakon_dsl.py`

```bash
python3 drakon_dsl.py to-drakon  in.dsl  out.drakon   # собрать диаграмму
python3 drakon_dsl.py to-dsl     in.drakon [out.dsl]  # разобрать на текст
python3 drakon_dsl.py roundtrip  in.drakon [out.dsl]  # тест: .drakon -> DSL -> .drakon,
                                                       # печатает OK или diff
```

### Синтаксис

```text
# Название диаграммы                        заголовок
> Условие старта: ...                       params (можно несколько строк)
% Краткое описание                          description

@ Имя ветки                                ветка силуэта; порядок в файле = branchId слева направо
  Действие                                 action
  Другое действие [20 мин]                 action + duration (side)
  // пояснение                             comment
  >> Подпроцесс                            insertion (вызов другой диаграммы)
  << Дождаться события                     simpleinput
  >! Выдать сигнал                         simpleoutput
  ? Вопрос?                                question; flag1=1 (Да вниз)
    да:                                    one (вниз)
      ...
    нет:                                   two (вправо)
      ...
  * Что выбираем?                          select
    - Вариант 1:                           case; последний с пустым текстом = "остальные"
      ...
    - (остальные):
      ...
  ~ цикл: Повторить 10 раз                 loopbegin; после цикла идём в '-> X' ниже
    тело цикла
  ~ /цикл[: текст] [-> Ветка]              loopend; текст идёт в loopend.content
  петля                                    arrow-loop (точка возврата)
  -> Имя ветки                             переход на ветку
  -> КОНЕЦ                                 переход на end
  -> повтор                                внутри цикла: конец итерации
  -> петля                                 возврат к метке 'петля' в этой ветке
```

Каждый путь обязан заканчиваться переходом. Внутри цикла пустой блок
`да:` / `нет:` означает «конец итерации» (== `-> повтор`) — DrakonHub
не умеет тянуть цикл через `two`-ветку вопроса (падает в `findLoopStart`),
так что используйте именно пустой блок для «продолжить», а выход из цикла —
через переход на другую ветку.

### Известные нормализации round-trip

Round-trip сравнивает два уровня:
1. **Точное совпадение графа** — если прошло, графы идентичны.
2. **Совпадение потоков** (множества путей от старта до терминатора) —
   если точного совпадения нет, но потоки совпадают, граф был развёрнут:
   общие иконки (в которые сходятся две ветки) продублированы.
   Семантически идентично, но топология иная.

Полный шаблон с циклом и select: `templates/workout.dsl`.

## 7. Просмотр без DrakonHub: SVG и карта координат

`scripts/drakon_render.py` считает раскладку по правилам силуэта (заголовки
веток на строке 0 слева направо, вертел вниз, правая ветка вопроса — вправо)
и выдаёт два вида:

```bash
python3 drakon_render.py svg in.drakon out.svg   # картинка - для человека
python3 drakon_render.py map in.drakon           # карта координат - для агента
```

**`svg`** — настоящий вектор: прямоугольники действий, ромбы вопросов,
пунктирные стрелки на чужие ветки. Чтобы посмотреть схему, не открывая редактор.

**`map`** — то, что агент реально «видит»: таблица (ветка, строка, колонка,
тип, текст) плюс проверки правил DRAKON по координатам:

```
ПРОВЕРКИ:
  пересечений клеток: нет
  two-ветвлений влево или в свою колонку: нет
  заголовки веток на строке 0: да
  порядок веток слева направо: [0, 1, 2, ...]
  межветочных переходов: 26 (из них назад-влево: 8)
```

По карте агент проверяет «начало слева сверху», «ветвление только вправо»
и отсутствие наложений — не запуская DrakonHub. Межветочные переходы
«назад-влево» — это норма: так рисуются возвраты на ветку (паттерн
«Lunch break»), а не нарушение правила.

Важно: SVG агенту как картинка бесполезен — он читает текст. SVG нужен
человеку; агенту нужна `map` (или DSL/псевдокод из разделов 5–6).

## 8. Частые ошибки

| Ошибка | Как правильно |
|---|---|
| `style` как вложенный объект | `"style": "{\"iconBack\":\"#ffffff\"}"` — строка |
| Ключи items числами | Ключи JSON всегда строки: `"1"` |
| `flag1` забыт у `question` | Ставь явно: `1` → `one`=Да |
| Два `end` | Один `end` на диаграмму |
| Ветка влево / пересечения | Ветвление только вправо; DrakonHub сам строит геометрию |
| Вопрос с «не/и/или» | Перефразировать или разбить на два `question` |
| Действие-существительное («CRM») | Команда: «Сохранить клиента в CRM» |
| `loopend` без `loopbegin` и наоборот | Цикл всегда парой |
| `select` без `case` | Минимум 2 `case`, последний — «остальные случаи» |
| Пустой `content` у `question`/`select`/`loopbegin` | Генератор кода падает на пустом тексте |
| Тип `foreach` в JSON | Его нет: пара `loopbegin`+`loopend` |

### Ограничения, выявленные практикой (Tauri Desktop)

**Главное: прямой возврат `one` на более раннюю иконку внутри ветки
подвешивает редактор.** Обходчик `layoutSilhouette` / `buildManhattan` идёт
вниз, натыкается на возврат, идёт снова — бесконечный цикл, приложение
зависает без ошибки.

### 8.1 Проверенные правила построения

Формальный визуальный синтаксис языка — тезисы 1–37 Паронджанова:
<https://drakon.su/jazyk/vizualnyj_sintaksis>. Сверка канона с практикой
DrakonHub — в `reference/engine-rules.md`.

Полный список правил (8 штук), симптомы и способ построения —
`reference/engine-rules.md`. Кратко:

- один вход на узел;
- ветка не может заканчиваться в середине силуэта
  (несколько входов в ветку — разрешены);
- `end` — только в последней ветке;
- из тела цикла все выходы — в `loopend`;
- на чужую ветку уводит только `two` вопроса, не `one`.

### 8.2 Проверка генератором кода (кнопка «ИИ промпт»)

Кнопка «ИИ промпт» / генерация псевдокода — это `drakongen.js`. Он
накладывает **свои** требования, которых нет ни в `drakon_tool.py check`,
ни в `drakon_try.py render`: диаграмма может рисоваться и не виснуть, но
псевдокод из неё не соберётся. Разбор ошибок, текст проверок и способ
проверить файл локально — `reference/code-generator.md`.

Главное правило: **все выходы из тела цикла сводите в `loopend`**, а
ветвление по причине выхода делайте в отдельной ветке после `loopend.one`.

Цикл замыкайте только двумя каноническими способами (так сделано во всех
официальных примерах):

1. **Пара `loopbegin` / `loopend`.** Тело — цепочка от `loopbegin.one` до
   `loopend`; повтор итерации рисуется автоматически. Досрочный выход —
   `two` вопроса внутри тела, уводящее **в `loopend`** (§ 8.2: выход мимо
   `loopend` ломает генератор кода). `loopend.one` — что делать после
   завершения цикла; там и разбирайте причину выхода.
2. **Переход на id ветки** (`one: "b1"`), как в примере «Lunch break»,
   где ветка «Eat» возвращается сама на себя. `loopend.one -> branch`
   тоже допустим — так сделано в официальном примере «A-star algorithm».
3. **`arrow-loop`** как точка возврата, как в «Work out - question-action».

**Топология вертела после `loopend`:** в DRAKON цикл `loopbegin`/`loopend`
закрывает свой скевер. После `loopend` на основном скевере ветки идти
**нельзя** — `findLeftLinks` ожидает, что вертел ветки заканчивается на
`loopend` (или на терминале), и падает с `node.down is undefined`.
Завершение выносите в **отдельную ветку**, а `loopend.one` ссылается на
неё — паттерн «A-star». Всё, что идёт «после цикла», включая фиксацию
результата и отчёт, — в новой ветке, а не в той же.

Дополнительно:
- **Нельзя: цикл `loopbegin`/`loopend` внутри ветки + возврат на эту же
  ветку изнутри неё.** Такого сочетания нет ни в одном официальном примере,
  и `findLeftLinks` на нём зацикливается (таймаут в `findLink`).
  Разрешённые варианты: возврат на свою ветку **без** цикла
  (паттерн «Lunch break»), либо цикл с переходом на **другую** ветку
  (паттерн «A-star», где `loopend 125 -> 32` и `121 -> 43` — обе ссылки
  идут из других веток).
- Держите **один** возврат на ветку: несколько возвратов на один `branch`
  повышают риск зацикливания `findLeftLinks`.
- Межветочные переходы указывайте на id ветки, а не на конкретную иконку
  в другой ветке.
- `comment` в межветочном переходе (`one` уходит в другую ветку) —
  риск; текст лучше перенести в `description` диаграммы.

`scripts/drakon_tool.py check` ловит эти случаи автоматически:
возврат назад по ветке — ошибка, несколько возвратов на ветку — замечание.
