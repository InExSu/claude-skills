# DrakonHub — диаграммы ДРАКОН из текста

Превращает обычный текст в JSON-файл с диаграммой ДРАКОН (`.drakon`)
и структурированные ментальные карты (`.graf`).
Просмотр — [DrakonHub](https://drakonhub.com/) Степана Митькина.

> JSON руками не пиши. Пиши DSL, собирай скриптом, проверяй скриптом.

## Когда применять и когда нет

Применяй: алгоритм, инструкция, регламент, разбор «что делать, если…» —
всё, что сводится к шагам, вопросам и циклам.

Не применяй:

- процесс с событиями, таймерами, ролями, компенсациями — это BPMN, не ДРАКОН;
- текст, который не сворачивается в структуру (возвраты «в любой момент»,
  пересекающиеся циклы) — верни отказ с диагнозом, а не выдуманную схему;
- ментальные карты строй как `.graf`, а не как диаграмму.

## Правила языка ДРАКОН

Визуальные (проверяет `check`, частично — рендер):

- поток сверху вниз, стрелок нет;
- ветвление только вправо, линии не пересекаются;
- «чем правее, тем хуже»: счастливый путь идёт прямо вниз, сбои уходят вправо;
- ровно один `end`, ровно один `header`; `end` — только в последней ветке;
- циклы — только парой `loopbegin`/`loopend`; самодельная петля `arrow-loop`
  внутрь ветки зацикливает движок. Все выходы из тела цикла ведут в
  `loopend`, разбор причины — после него, в своей ветке;
- ветвление делается `question`, а не переходом `one` на чужую ветку:
  на другую ветку уводит только `two`. Полный свод ограничений движка —
  [reference/engine-rules.md](reference/engine-rules.md).

Текстовые (часть проверяет `check` как замечания):

- одна иконка = один шаг;
- действия — императив («Сделать X»), без точки в конце;
- вопросы — атомарные, без *и* / *или* / отрицания
  («Товар в наличии?», а не «Товар в наличии и оплачен?»);
- заголовок диаграммы — в `header.content`.

## Конвейер «текст → диаграмма»

1. Выдели шаги (действия), развилки (вопросы с ответами да/нет),
   повторения (циклы), варианты (выбор).
2. Определи главную ветку (прямой путь вниз) и ответвления вправо.
3. Запиши DSL (раздел ниже), собери и проверь.
4. Прочитай результат через `read` — псевдокод должен звучать как исходный текст.
5. Не сошлось — упрости текст, а не схему. Отказ — валидный исход.

LLM отвечает только за понимание текста (шаги 1–2).
Сворачивание в схему — детерминированное, его делают скрипты.

## DSL: пиши это вместо JSON

Отступы — пробелы, вложенность — отступом. Пустые строки игнорируются.

```
# Тренировка                          заголовок (первая строка)
> Условие: спортзал, есть 40 минут    комментарий к следующей иконке
* Выноска на полях                    свободная выноска
@ Разминка                            ветка силуэта (без @ — одна ветка 0)
Выполнить суставную разминку          действие
? Устал?                              вопрос
  да:                                 ветка «да» (также yes:)
    Остановиться
  нет:                                ветка «нет» (также no:)
    Продолжить
$ Что дальше?                         выбор (select)
  = Вариант 1                         вариант (пустой = по умолчанию)
    Сделать первое
  = Вариант 2
    Сделать второе
~ Повторить 10 раз                    цикл (тело — вложенные строки)
  Поднять вес
^                                     переход; внутри ~ — возврат к началу
% 2 мин                               длительность (ребёнок действия)
<< Ждать событие / >> Ответить        ввод / вывод (simpleinput / simpleoutput)
+ Вставка / & Адрес                   insertion / address
```

Экранирование: `\n` внутри строки — перевод строки в тексте иконки,
ведущий маркер (`? Что?` как действие) — обратным слэшем `\? Что?`.

## Скрипты (Python 3, только стандартная библиотека)

```bash
cd drakonhub

# Проверка: схема импорта DrakonHub + правила ДРАКОН
python3 scripts/drakon_tool.py check templates/choice-and-loop.drakon
#   → OK: ошибок и замечаний нет

# Чтение: диаграмма как псевдокод, по веткам силуэта
python3 scripts/drakon_tool.py read templates/minimal.drakon
# Чтение ментальной карты как план
python3 scripts/drakon_tool.py read templates/mind-map.graf

# DSL ⇄ JSON
python3 scripts/drakon_dsl.py to-drakon templates/workout.dsl out.drakon
python3 scripts/drakon_dsl.py to-dsl    out.drakon out.dsl
python3 scripts/drakon_dsl.py roundtrip templates/minimal.drakon
#   → OK: графы совпали (6 узлов)

# Раскладка и рендер
python3 scripts/drakon_render.py svg templates/silhouette.drakon out.svg
python3 scripts/drakon_render.py map templates/silhouette.drakon

# Строгая проверка реальным движком (импорт → открытие → рендер)
python3 scripts/drakon_try.py render out.drakon   # OK nodes=N | HANG | ERROR <текст>
python3 scripts/drakon_try.py stack  out.drakon   # стек места зависания
```

`check` ловит только формализуемые ловушки; редактор может зависнуть на
конструкции, которую чекер считает корректной. Перед выдачей файла
пользователю прогоняйте `drakon_try.py render` — правило
[reference/engine-rules.md](reference/engine-rules.md).
`drakon_try.py` требует `node`, `playwright` и chromium; без них он
пропускается с понятным сообщением, остальные скрипты работают всегда.

`roundtrip` сравнивает каноническую форму (DSL→DSL):
повторно используемые узлы и цепочки комментариев нормализуются.
Подробности — в [reference/file-format.md](reference/file-format.md).

## Семантика иконок (кратко)

| Иконка | Связи | Смысл |
|---|---|---|
| `action` | `one` | один шаг, императив |
| `question` | `one` (да при `flag1=1`), `two` | вопрос с двумя выходами |
| `select` | `one` → первый `case` | выбор из N вариантов |
| `case` | `one` (тело), `two` (следующий) | вариант; у последнего нет `two` |
| `branch` | `one` | ветка силуэта; `branchId` 0 — главная |
| `loopbegin` / `loopend` | `one` | скобки цикла |
| `arrow-loop` | `one`, без текста | явный переход (обычно назад) |
| `comment` | `one` (к кому) | пометка, в потоке прозрачна |
| `duration` | никуда (через `action.side`) | подпись длительности |
| `callout` | нет | свободная выноска |
| `header` / `end` | нет | заголовок (с `content`) / конец |

Полная спецификация — в [reference/file-format.md](reference/file-format.md).

## Чеклист перед выдачей файла пользователю

- [ ] `check` — `OK: ошибок и замечаний нет`
- [ ] `roundtrip` — `OK: графы совпали`
- [ ] `drakon_try.py render` — `OK` (нет `HANG` / `ERROR`)
- [ ] `read` звучит как исходный текст (шаги, вопросы, ветки на месте)
- [ ] счастливый путь идёт вниз, сбои — вправо
- [ ] вопросы без *и* / *или* / отрицания
- [ ] `end` — только в последней ветке; выходы из цикла — в `loopend`
- [ ] файл открывается на [drakonhub.com](https://drakonhub.com/) (импорт JSON)

## Главный принцип

> **Схема доказывает свою правильность через структуру:**
> прошла `check` → сошлась в `roundtrip` → открылась в реальном движке
> (`drakon_try.py`) → читается как текст → диаграмма верна.
